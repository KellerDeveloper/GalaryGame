# Правила проекта GalaryGame

GalaryGame — геймифицированное iOS-приложение для наведения цифрового порядка в фотогалерее и файлах (SwiftUI + SwiftData). Полная документация ведётся в Obsidian:
`/Users/dmitrijkeller/Documents/KELLER/Obsidian/KellerNotes/01 Projects/GalaryGame/`
(вход — `00 - GalaryGame (Индекс).md`).

## Рабочий процесс (обязательно)

1. **Сначала — документация.** Перед началом любой задачи прочитай доку в Obsidian (индекс + релевантные заметки 01–11), чтобы понимать что уже есть, НЕ дублировать существующий код и знать что за что отвечает.

2. **Уточняющие вопросы перед реализацией.** Прежде чем что-либо кодить — задай **минимум 3–4 уточняющих вопроса** (поведение, границы, приоритеты, крайние случаи). Не додумывай за пользователя.

3. **Сдача на проверку → доку → релиз-ноуты → пуш.** Закончив работу, **отдай результат пользователю на проверку** — не считай задачу закрытой сам. Только после явного «окей»:
   - актуализируй документацию в Obsidian (заметки по затронутой области);
   - **запиши релиз-ноут** (см. ниже);
   - закоммить изменения и запушь в git.

## Релиз-ноуты

После апрува дописывай изменения в дневник релиз-ноутов:
`.../01 Projects/GalaryGame/Release Notes/ГГГГ-ММ-ДД.md`

- **Один файл на день** (имя = сегодняшняя дата). Если файл на сегодня есть — дописывай пункт в него, не создавай новый.
- Внутри: заголовок `# ГГГГ-ММ-ДД`, затем пункты списком:
  `- ЧЧ:ММ — что изменилось`
- **Язык — человеческий, для игрока, а не для разработчика.** Пиши что стало и чем это полезно; где уместно — что было раньше и почему стало лучше. Без имён файлов, классов и техножаргона.
- Время `ЧЧ:ММ` бери реальное на момент записи (`date +%H:%M`).
- Это дневник изменений по датам. Заметки по версиям/сборкам (если появятся) — отдельно, по образцу папки `Releases/` в KellerRats.

## Порядок (Plan → Do → Verify)

- **План:** прочитал доку → задал 3–4 вопроса → сформулировал что делаю + критерии проверки.
- **Выполнение:** делаю строго по плану. Числа и API сверяю по исходникам, а не по доке (док может отставать; источник правды — код).
- **Проверка:** сборка/тесты, перечисление что проверил, сдача пользователю.
- **После апрува:** обновление доки + git push.

## Границы

- Меняй только то, что просили — без побочных правок в несвязанных местах.
- Не удаляй документацию без явной просьбы.
- Документация отражает состояние проекта, но **источник правды — код**.

## Стек и структура

```
GalaryGame/
├── App/            точка входа, глобальный стейт (GameStore)
├── Models/         SwiftData-модели + enum'ы правил
├── Engine/         pure-логика (Scoring/Gamification/Quest) — покрыта тестами
├── Services/       обёртки iOS API (Photos, Files, Vision, Supabase)
├── Features/       SwiftUI-экраны
└── DesignSystem/   тема, DOSRing, AssetImage
```

Билд — через MCP `BuildProject` (xcode-tools). Тесты — фреймворк Testing / XCTest.
